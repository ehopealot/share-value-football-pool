# T10 Structural Convergence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Converge the Worker composition, season read model, confirmation protocols, and deterministic browser harness without changing pool authority, product capability, or production resources.

**Architecture:** Keep `PoolDO` authoritative and D1 a disposable canonical-offer/projection store. Split production `src/index.ts` from local `src/index.local.ts`; make `ReadPoolView` the one parsed lifecycle contract; use flow-local discriminated state machines whose review values are immutable snapshots; and make one lock-owning E2E fixture own build, migration, process group, persistence, diagnostics, and cleanup.

**Tech Stack:** TypeScript, Zod, React, Hono, Cloudflare Workers/Durable Objects/D1, Vitest, Playwright, checked-in Wrangler configuration, and local Wrangler binary resolution.

**Spec:** [`docs/superpowers/specs/2026-08-23-t10-structural-convergence-design.md`](../specs/2026-08-23-t10-structural-convergence-design.md)

## Design notes
- `src/index.ts` must be production-only: production auth/app construction, `PoolDO` export, and a buildable fail-closed `EmailSender`; it must not import `worker/test-controls`, `DevelopmentMailbox`, local fixture modules, impersonation headers, `LOCAL_TEST_CONTROLS`, or `/__local-test` handlers. `src/index.local.ts` composes the same production behavior with loopback-only local identity, deterministic fixtures/alarm/projection controls, mailbox inspection, and a one-shot outbound response barrier. If it wraps the DO it must still export the configured `PoolDO` class identity.
- Add a local Wrangler config whose D1 binding/migrations, DO binding/class/migrations, Queue producer/consumer, R2, assets, compatibility date/flags, and cron match `wrangler.jsonc`; entry selection and local variables/routes are the only allowed differences. Add `scripts/verify-wrangler-parity.mjs`, `scripts/verify-production-artifact.mjs`, `scripts/production-route-probe.ts`, `scripts/verify-owned-resource-cleanup.mjs`, `scripts/local-smoke.ts`, and `scripts/run-t10-serial-gate.mjs`; expose their exact package scripts plus `build:local`, `test:local-smoke`, and `start:production-probe`. Use mode-selected checked-in Wrangler configuration and distinct production/local output roots so both entries build independently without artifact collision; the artifact verifier must inspect the production manifest after both builds. `start:production-probe` is bounded, readiness-checked, and self-cleaning, or the serial runner owns it in an outer `finally`.
- Replace the current overloaded `activeSeasonId`/`season`/`orders` read shape with exported Zod `ReadPoolView` in `src/contracts/http.ts`: `activeSeason`, `nextDraftSeason`, `latestClosedSeason`, season-scoped balances, member directory `{memberId,displayName,role,status}`, and commissioner-only `{seasonOrders}` (otherwise `null`). IDs/timestamps/micros are strings except stated nullable fields. Select closed history by `closed_at DESC, id ASC`. Unauthorized/nonmember requests remain gate denials rather than partial views.
- Migrate `pool-do`, Worker routes/API parser, `OverviewPage`, `AdminOrdersPage`, `AdminSeasonPage`, and all view-dependent navigation/history/standings/activity readers together. No-active, draft, active, and closed-history notices must coexist independently. A closed history does not prevent create draft, configure/open, then quote/execute an order. The loopback close fixture only arranges a legitimately closed state and never adds public close permission.
- Define shared Zod request/snapshot/projection contracts at the Worker/UI boundary. Quote requests are constructible before a quote and carry only semantic input plus browser `quoteKey` (`commandId`) and `wagerId`; successful straight/teaser snapshots contain all authoritative terms and `commandVersion`; share snapshots contain all order terms. Validate canonical decimal/timestamp/odds, proof mirroring, straight null/line rules, teaser direction/selection/count rules, and 10-point exactly-three rule. `acceptedOdds`, not a ticket-price-micros field, is the accepted wager price. Display profit/return/line strings are derived only.
- Persist an authoritative `(actorId, quoteKey)` quote record in PoolDO. Placement contains distinct `mutationKey`, `quoteKey`, `wagerId`, and unchanged `quotedCommandVersion`; Worker performs exact mutation replay before D1 revalidation, and PoolDO replay before transaction validation. New placement transaction compares every submitted placement term and current version with the record before balance/lock/wager/ledger mutation. Altered terms/version return `LINE_CHANGED` or `ORDER_QUOTE_STALE` without mutation. Retryable/lost responses retain exactly the reviewed snapshot and keys; terminal/stale errors retire the rejected quote/mutation keys, return to editing, and require a fresh browser quote key (and new wager ID after semantic edit).
- Each of `OddsPage`, `TeaserPage`, and `AdminOrdersPage` uses its own discriminated `editing | quoting | reviewing | submitting` state. The review component gets only a reviewing snapshot, never editor values, setters, callbacks, or selectors. Controls are disabled and quote/submit is single-flight. Preserve all existing privacy/redaction, accounting, source proof, stale/locked, idempotency, reversal, and automatic close behavior.
- The E2E owner in `e2e/fixtures/local-worker.ts` needs worker-scoped build, test-scoped tagged isolated persistence, direct local Wrangler CLI (not `npx`), migrations, detached process group, immediate stdout/stderr 64KiB ring drains with truncation markers, health readiness, outer-finally TERM/KILL cleanup, direct process-group existence check, and tagged-only resource removal. A checkout lock serializes the acceptance runner. Local transport fault controls delay/drop only a completed real outbound response and fabricate nothing.

## Risks
- The current Worker entry mixes `DevelopmentMailbox`, test controls, impersonation, and fixture routing; prove generated production output rather than relying on source intent.
- `ReadPoolView` is a broad consumer migration; forbid fallback reads of `season`, `orders`, and unscoped member balances once the contract is introduced.
- Replay must precede D1 freshness only for an exact stored mutation. Fingerprint conflicts and altered quote bindings must remain fail-closed.
- The existing owner uses `npx`, random ports, spawned `ps`, and pipe backpressure risk. Bound diagnostics and preserve the primary error during cleanup.

- [ ] Define separately constructible Zod schemas/types in `src/contracts/commands.ts` and `src/contracts/http.ts` for browser quote HTTP input, authenticated semantic quote identity/fingerprint, and trusted Worker-to-PoolDO complete canonical quote projection; migrate `src/durable/pool-commands.ts`, `src/worker/routes.ts`, and `src/worker/offer-quotes.ts` from browser-provided placement tickets to quote request/snapshot/placement projections. - [ ] Green the expanded focused suite plus `npm run test:local-smoke` using semantic quote/snapshot/quoteKey/quotedCommandVersion placement requests and `npm run typecheck`; prove exact stored replay precedes D1, canonical snapshot replay remains valid after D1 changes/locks, and conflicts leave no mutation.
